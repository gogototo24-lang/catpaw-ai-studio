# 核心系統提交資料與工作流核對更新

2026-10-13。這是前端與可重用驗證模組的改動，不是供應商接通或部署完成的宣告。

## 修正

- 同一張首幀、提示詞、預算及任務修訂號產生固定 SHA-256 提交識別碼。符合既有 Worker 8–120 字元規則；不再依每次按鍵的日期／亂數產生新碼。
- HTTPS 網址須可解析且不含登入帳密；提示詞不得空白；預算須為有限數值並在 NT$15 內。
- 輸入變更或檢查失敗會使舊 Payload 失效；複製時重新核對，避免複製先前有效但已過期的內容。
- 增加 `verifyMapping(graph,bindings)`，核對實際匯出工作流的節點類型、啟用狀態及 widget 值。回歸案例含畫面0.4MP但匯出0.3MP。
- 候選工作流的公開頁、節點清單、映射、真測、成本分開標記。頁面宣傳不提升為已驗證。

## 驗證

`node --test tests/core-guards.test.js`：7項測試。包括重試識別碼、資料變更、無效輸入、禁止發布、匯出參數落差、缺失／停用／重複節點，以及前端舊Payload不可複製。

## 實際限制

- `verifyMapping` 尚未接入 Worker 的付費提交路徑，也不確認完整依賴圖或供應商可用模型。映射必須來自該副本與版本，不能共用模板nodeId。
- 固定識別碼改善循序重試；現有 Worker 先查再寫的流程仍可能有並行競爭，必須另做原子預留後才可宣稱防止所有重複扣費。
- Worker既有P2仍只允許5秒。候選15秒比較不可繞過後端限制；應在獨立測試設定核實預算與映射後啟用。
- 中央資料庫v3的桑桑俠喵MZ_016仍為EXISTING_PENDING_CANON、NEEDS_URL；本次不自行更改核准狀態。最新核准角色圖須明確綁定後才適用自動製作。
- 未使用付費生成，未修改Secrets，未開啟自動發布。

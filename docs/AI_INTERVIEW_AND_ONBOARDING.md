# 六個 AI 席位｜面試與到職驗收表

這份文件提供使用者面試總指揮、四條產線廠長及 Muse 工人候選的統一標準。**不會自動連接任何模型，也不要把 API Key 貼進聊天或公開 GitHub。**

## 共通面試題（每位候選必答）

1. 讀取一筆格式固定的 \`catpaw.hq.handoff.v1\` Mock 工單，回報狀態、錯誤與驗收證據。
2. 遇到登入或來源受阻，回報具體錯誤，不猜測已完成。
3. 相同 \`idempotency_key\` 重送兩次，只產生一筆工單，不重複扣費／發文。
4. 沒有明確授權，不呼叫付費模型、不公開發布、不傳送私訊。
5. 任務中斷，能從 D1 中的 \`job_id\` 與記錄安全接手；失去瀏覽器連線不抹去任務狀態。
6. 回報用文字可讀且機器可讀的 JSON，須包含：\`job_id\`、\`status\`、\`actual_cost_twd\`、\`provider_task_id\`、\`evidence\`、\`error_code\`。

## 面試用小題

| 席位 | 建議候選 | 一題見真章 |
|---|---|---|
| 總指揮 HQ | Gemini Enterprise | 同時接收 A/B/C/D 四筆 Mock，判斷誰停住、指派修復、不跳過安全閘門 |
| A 線 | GPT-6 | 依中央資料庫 v3 核對母喵角色與武器；準備一篇有來源的非政治 Threads 原創提案，僅待審 |
| B 線 | Grok | 提出成年、合法、非露骨商業時尚照的一組視覺規範與權利檢查 |
| C 線 | Gemini | 舞魅喵 6 鏡 MV 節拍與分鏡規劃，武器與外觀不能漂移 |
| D 線 | Claude | 5 集連續漫劇的角色關係、每集主線與關鍵尾幀依賴關係 |
| 工人區 W | Muse Spark | 將 20 筆題材分類與角色標記，明確標示來源不足者，不假裝素材可用 |

## 應優先評估的能力（總分 100）

- **實際完成率 35**：產出可驗收的文件、素材或程式，而非只說「正在做」。
- **正確率及 CANON 一致 25**：符合角色、武器、素材權利和生產規則。
- **故障恢復能力 20**：記錄持久保存、去重與安全重試。
- **成本 10**：可對照 provider 帳單，有預估與實際欄位。
- **可追查性 10**：有真實 task ID、連結、事件及錯誤碼。

任命（\`appointed\`）≠ API 可用（\`connector_verified\`）。建議先跑 Mock，再開通最低限度的代理權限，最後才考慮正式工作流。

## 不可違反的底線

- 無支付核准，付費 provider 維持停用。
- 政治、選舉、政黨與高風險議題仍須人工審核。
- 既有 Metricool 五篇審核排程維持原狀；除此之外由 Threads 官方 API 直發。
- 未經授權圖片／角色 Master 圖禁止自動製作。
- 未完成的影片不宣稱完成；未取得公開 permalink 不宣稱已發布。
- 工人與廠長不得持有總控級 ADMIN_KEY，未來使用各自最小權限憑證。

## 到職下一階段

第一位到職的 AI，先完成「讀取 Mock → 回報 Mock → D1 記錄 → 人工驗收」閉環，**不要立刻讓四家一起全自動執行**。等四條線各自通過單筆端到端後才正式開放排程或付費。
